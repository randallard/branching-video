# ADR-0005: Vite multi-page build replaces the no-build static HTML
- Status: Superseded by [ADR-0020](0020-vite-multi-page-build-with-relative-base.md)
- Date: 2026-09-14
- Deciders: Ryan

## Context
The site is five standalone pages (`index`, `player`, `studio`, `editor`, `create`), each with
inline CSS and JS, served as-is by `serve` in dev and by Pages from the branch root. Strict
TypeScript ([ADR-0004](0004-provable-lite-strict-typescript-and-property-tests.md)) needs a
compile step, and sharing a core across pages needs module bundling.

Deep links are part of the product: `player.html#node-id` and `player.html?config=live/x.json`
are pasted into YouTube cards and descriptions, so page URLs must not change.

## Decision
Build with **Vite** in multi-page mode: each existing HTML file stays at its current path and
becomes a Vite entry that loads a TypeScript module. Files fetched at runtime rather than
imported — `live/*.json`, `live/manifest.json`, `config.json`, `config.example.json` — move to
`public/` so they are copied to the same URLs in `dist/`. `vite.config.ts` sets
`base: "/branching-video/"`. `pnpm dev` (Vite) replaces `serve`.

## Alternatives considered
- **Single-page app with client-side routing** — rejected: changes every published URL, and
  the hash is already used for node ids.
- **`tsc` only, no bundler** — rejected: works for one page, but shared modules across five
  pages plus Pages' base path is what a bundler is for; cycle-in already uses Vite.

## Consequences
- `index.html` and `editor.html` discover shows by fetching the `live/` *directory listing*,
  which only `serve` provides; they fall back to `live/manifest.json`. Under Vite dev there is
  no directory listing, so discovery must go through the manifest in both dev and production
  (regenerated by `pnpm manifest`, which could run as part of `pnpm build`).
- Forkers need Node + pnpm to change code; changing only shows (`public/live/*.json`) still
  needs nothing but a push, because CI builds.
