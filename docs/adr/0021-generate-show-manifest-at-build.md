# ADR-0021: Generate live/manifest.json from public/live in dev and at build
- Status: Proposed
- Date: 2026-09-14
- Deciders: Ryan (pending — implemented in slice 2 for review)

## Context
The home page and Editor's Configs menu list published shows. They used to prefer `serve`'s HTML
directory listing of `live/` and fall back to a committed `live/manifest.json`, regenerated by
hand with `pnpm manifest` — a step that was easy to forget (a new show plays by URL but never
appears on the home page). Vite has no directory listing, so after
[ADR-0020](0020-vite-multi-page-build-with-relative-base.md) the manifest is the only discovery
path, which makes a stale one a visible bug rather than a fallback's.

## Decision
A small Vite plugin in `vite.config.ts` builds the manifest from `public/live/*.json` with the pure
`buildManifest` in `src/core/manifest.ts`: served from memory at `/live/manifest.json` by the dev
server, and emitted into `dist/live/` at build. The manifest is no longer committed and
`pnpm manifest` is gone. Pages read only the manifest.

## Consequences
- Adding a show is: put the JSON in `public/live/`, push. No second step to forget.
- The manifest is sorted by filename in code-unit order rather than `localeCompare`, so it is
  identical on every machine.
- Anything reading `live/manifest.json` from the repository checkout (rather than the site) no
  longer finds it; nothing known does.
